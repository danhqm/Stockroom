# Stockroom Backend Implementation Plan

> For agentic workers: use superpowers:executing-plans task by task.

Goal: a tested Laravel JSON API for receiving purchased stock with human review.
Architecture: single Laravel application, MySQL transactions, append-only stock movements and database queue. React connects later using session cookies and CSRF.
Tech stack: Laravel 13, PHP 8.4, MySQL 8.4, Docker Compose, OpenAI.
Spec: ../../backend-design.md (approved by user).

## Global constraints
One shop/location; manager and staff; integer quantities; no AWS; no public signup; AI never updates stock; MySQL tests use a dedicated database. No UI design in this phase.

## Review focus
Concurrent receives/reversals; stale draft edits after confirmation; same idempotency key with different data; all-damaged receipts; malformed/unreadable extraction. Tests below pin these behaviours.

## Task 2 — Catalogue and purchasing

Interfaces: products/suppliers list/create/update; purchase-orders list/create/show/update/issue/close.
- [ ] Tests: staff cannot manage, unique SKU, duplicate product lines rejected, positive integer quantity, issued order immutable, close requires reason.

- [ ] Run PurchasingTest against MySQL.

## Task 3 — Receipt review, stock and correction
Files: ReceiptController; ReceivingService; InventoryController; ReceivingTest; ConcurrencyTest.
Interfaces: receipts list/create/show/update/confirm/reverse; inventory and movements lists.
- [ ] Tests: order 10, receive 6 damaged 1 -> stock 5 outstanding 5; later 5 -> fulfilled; double confirm unchanged; overreceipt 422; off-order lines rejected.
- [ ] Tests: reused draft request key returns original; changed data conflicts; stale draft update rejected; zero usable receipt no movement; manager-only reversal requires reason and preserves closed orders.
- [ ] Implement transactions locking order, receipt then sorted product IDs; movement uniqueness by line/type; recompute order status; immutable receipt history.
- [ ] Run concurrent HTTP/process tests for competing receipts and repeat confirmation plus rollback tests.

## Task 4 — Document extraction
Files: ExtractionController; ExtractDeliveryNote job; DeliveryNoteExtractor; config/stockroom.php; ExtractionTest.
Interfaces: receipt document upload, extraction status/private image retrieval. Extraction output remains separate from reviewed receipt lines.
- [ ] Tests: JPEG/PNG validation and size/dimension limits; unauthenticated retrieval denied; invalid/null quantities not approved; failed provider leaves receipt editable; duplicate jobs do not spend twice or change inventory.
- [ ] Implement database queue, bounded provider request, structured output validation and budget reservation; disable provider by default.
- [ ] Run tests using HTTP fakes; live spend requires separately agreed allowance.
